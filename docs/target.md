# Мишень (target)

Мишень — набор связанных состояний иона, между которыми электрон вызывает
переходы. Качество сечений определяется в первую очередь качеством и
**согласованностью** волновых функций мишени.

## Объекты

```python
ion = db.Ion("Xe", 1)                 # элемент + заряд; ion.z, ion.nelc, ion.spectrum == "Xe II"
tg = db.Target(ion, core="[Kr]4d10",  # замкнутый остов; можно "1s 2s 2p 3s ..." или "[Xe]4f14"
               workdir="target",
               grid={"rmax": 50.0, "hmax": 0.5},   # B-сплайны (knot.dat)
               max_it=75,                           # итераций dbsr_hf
               hf_args={})                          # любые параметры dbsr_hf для всех расчётов
```

### Сетка B-сплайнов

* `rmax` — **радиус R-матрицы a**. Все орбитали мишени должны обращаться в ноль
  до `rmax` (стресс-тест это проверяет). Для Xe⁺ с 7s хватает 50 a₀; для
  ридберговских состояний (n ≥ 8) нужно больше. Слишком большой `rmax`
  увеличивает число сплайнов и размер матриц.
* `hmax` — максимальный шаг сетки при больших r. Континуум с импульсом k
  описывается, пока k·hmax ≲ 1: для электронов до ~60 эВ (k ≈ 2.1) берите
  `hmax ≤ 0.5`. Слишком крупный шаг — сечения при высоких энергиях неверны.
* Сетка общая для мишени и рассеяния; `Scattering` берёт её из мишени.

## Конфигурации: `tg.add()`

```python
tg.add("5s2 5p5")                               # 1-я — опорная: оптимизируются ВСЕ орбитали
tg.add("5s2 5p4 6p")                            # дальше: только новые орбитали (6p-, 6p)
tg.add(["5s 5p6", "5s2 5p4 5d"])                # список = один КВ-расчёт, общий набор орбиталей
tg.add(["5s 5p6", "5s2 5p4 5d"], correlation=["5s2 5p4 6d"])   # + корреляционная орбиталь
tg.add(["5s2 5p5", "5s2 5p4 6p"])               # список с опорной конфигурацией: заменяет её состояния
```

Конфигурация пишется только внешними оболочками (без остова), в обычной
нерелятивистской записи. pydbsr сам строит jj-подоболочки.

### Какие орбитали оптимизируются (`varied`)

* Для первой (опорной) — все (`varied="all"`): получаются орбитали остова и
  5s, 5p самосогласованно для основного состояния иона.
* Для остальных — по умолчанию только орбитали, которых нет в опорной
  (например, для 5p⁴6p — `6p-,6p`). Остов общий — орбитальный набор компактный.
* Явно: `tg.add("5s2 5p4 6p", varied="6p,5p")`. **В DBSR `6p` означает только
  p₃/₂**, `6p-` — p₁/₂. pydbsr разворачивает `6p` в `6p-,6p`. Если нужно
  варьировать одну подоболочку, пишите `6p-` явно. (Раньше из-за этого p₁/₂
  оставалась нулевым приближением, и состояния с 6p₁/₂ уходили на эВ вверх.)

### Один КВ на чётность — почему это важно

Состояния из **разных** расчётов не являются собственными состояниями одного
гамильтониана: у них ненулевые ⟨i|H|j⟩. dbsr_mat3 пишет об этом в `mat_log.nnn`
(«Target hamiltonian errors»), а в уравнениях сильной связи это превращается в
паразитную связь каналов. Для Xe⁺ при раздельном счёте 6s и 5d она доходила до
0.1 а.у.; объединение изменило Ω на 20 % в медиане и в 2–3 раза для отдельных
переходов.

**Правило:** все состояния одной чётности, которые смешиваются (близкие по
энергии, та же J), — одним списком в `tg.add([...])`. Основное состояние можно
включить в КВ с возбуждёнными той же чётности: `tg.add(["5s2 5p5", "5s2 5p4 6p"])`
— орбитали опорного расчёта остаются входными, а его состояния заменяются.

Проверка: `sc.target_errors()` после dbsr_mat3 — `h` и `s` должны быть ~0.

### Корреляционные орбитали (`correlation=`)

Проблема: орбиталь 5d в Xe⁺ сильно зависит от терма родительского остова
5p⁴(³P, ¹D, ¹S). Одна общая 5d даёт ошибки уровней до 2–3 эВ.

Решение: добавить конфигурацию с корреляционной орбиталью (5p⁴6d) и
переоптимизировать 5d и 6d (dbsr_mchf) **по физическим состояниям**:

```python
tg.add(["5s 5p6", "5s2 5p4 5d", "5s2 5p4 6s", "5s2 5p4 7s"],
       correlation=["5s2 5p4 6d"], mchf_max_it=150)
```
* 6d становится не спектроскопической, а корреляционной орбиталью: смесь 5d и 6d
  разная для разных термов → термозависимость;
* dbsr_mchf оптимизирует нижние N_phys уровней в каждом J, где N_phys — число
  CSF физических конфигураций; остаются только физические состояния;
* все состояния — из одного расчёта → ортогональны;
* при рассеянии континуум делается ортогональным к корреляционным орбиталям
  (`<kd|6d>=0`), иначе разные каналы порождают одинаковые (N+1)-функции и
  dbsr_hd3 падает (DPOTRF). Это делает pydbsr автоматически.

Результат для Xe⁺: группа 5s5p⁶+5p⁴5d — rms 0.35–0.45 эВ против NIST (было 0.8,
максимум 2.7 эВ).

`tg.refine()` — альтернатива (свои орбитали для каждого родительского терма),
но состояния разных групп **неортогональны**: годится только для структурных
расчётов (энергии, силы осцилляторов), **не для рассеяния**.

### Другие параметры `add`

| Параметр | Смысл |
|---|---|
| `name` | имя расчёта (по умолчанию из конфигураций) |
| `term="LS"` | первый шаг dbsr_hf: `LS` (по термам), `AV` (среднее по конфигурации), `jj` |
| `jj_varied="none"` | что варьировать на втором (jj) шаге |
| `ci=True` | после dbsr_hf ещё dbsr_breit3 + dbsr_ci3 (КВ с брейтовскими поправками) |
| `mchf_varied` | орбитали для dbsr_mchf (по умолчанию — те же, что `varied`) |
| `**hf_args` | любые параметры dbsr_hf только для этого расчёта (`eol=1`, `mbreit=1`, …) |

## Расчёт и результат

```python
tg.compute(jobs=4)              # dbsr_hf для всех конфигураций (параллельно), затем разбиение на J-состояния
tg.states                       # список State: name, config, label, two_j, parity, energy, ...
print(tg.table())               # таблица: E (а.у.), ΔE (эВ), NIST (эВ)
tg.select(max_states=30, emax_ev=18, configs=["5s2 5p4 6p"])
tg.save(); tg = db.Target.load("target")      # json + файлы name.c / name.bsw
```
Повторный `compute()` пропускает готовые конфигурации (`force=True` — пересчитать).

Каждое состояние — пара файлов `name.c` (CSF и коэффициенты) и `name.bsw`
(орбитали) — формат DBSR, их можно использовать и без pydbsr.

## Отождествление с NIST

```python
db.nist.assign(tg.states, ion)                   # скачать с NIST (или строка "Xe II")
db.nist.assign(tg.states, db.nist.read_levels("xe2_levels.csv"))   # без интернета: сохранённая таблица
db.nist.assign(tg.states, reference.read_xlsx("CrossSectionsIon.xlsx").levels)
```
Состояния и уровни группируются по (открытые оболочки, J, чётность) и
сопоставляются по порядку энергии; для КВ-расчётов — с уровнями всех
конфигураций расчёта (доминирующая конфигурация в сильно перемешанных случаях
может не совпадать с обозначением NIST). Проставляются `exp_energy_cm`,
`nist_label`, `nist_no`. Неотождествлённые состояния выдаются предупреждением —
их обычно исключают из рассеяния:
```python
states = [s for s in tg.states if s.nist_no is not None]
```

## Орбитали: большие и малые компоненты

```python
from pydbsr import io
for f in io.radial_functions("target/5p5.bsw"):      # через утилиту bsw_rw
    print(f.name, f.kappa, f.energy, f.norm())       # f.r, f.P (большая), f.Q (малая)
```

## Проверьте перед рассеянием

* ΔE против NIST по группам (rms, максимум) — ошибки > 0.5 эВ для нужных
  уровней означают, что модель мишени надо улучшать;
* тонкая структура основного терма (ab initio, без подгонки);
* все нужные уровни отождествлены;
* орбитали обращаются в ноль до `rmax`.
