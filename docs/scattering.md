# Внутренняя область: расчёт рассеяния

```python
sc = db.Scattering(tg, "scat", states=states, jmax=25, exp_energies=True)
sc.prepare()            # копирует файлы мишени, пишет knot.dat, target_jj, dbsr_par
sc.run_prep()           # dbsr_prep3: общий набор орбиталей, пороги
sc.run_conf()           # dbsr_conf3: каналы и конфигурации каждой парциальной волны (cfg.nnn)
sc.run_streamed(cores=64, mem_gb=200, hd_threads=16)    # breit → mat → hd по волнам
```

## Парциальные волны

Система e + ион с N электронами имеет N+1 электрон; полный момент J — целый,
если N+1 чётно, полуцелый иначе (для Xe⁺, N+1 = 54, J целые). `jmax` задаёт
J = Jmin…Jmax обеих чётностей (`db.partial_waves(nelc, jmax)`);
произвольный список — `partial_waves=[(2J, чётность), ...]`.

**Сколько J нужно.**
* Запрещённые (не дипольные) переходы и переходы с переворотом спина
  сходятся быстро: обычно хватает J ≈ 10–20.
* **Дипольно разрешённые** переходы сходятся медленно: из-за дальнодействующей дипольной связи
  вклады парциальных волн убывают почти геометрически с отношением, близким к 1, при 50–100 эВ нужны J ~ 50 и
  больше или «top-up» (досуммирование по Кулону–Бете). В pydbsr top-up **не
  реализован**; смотрите сходимость по `cs.omega_pw` (см. [outer.md](outer.md)).
* Wang et al (2019) для Xe⁺: J ≤ 50.

## Ресурсы: сколько памяти и времени

```python
for d in sc.wave_sizes():
    print(d)   # klsp, two_j, parity, nch (каналы), khm (размер матрицы), mk, mat_gb, hd_gb, disk_gb
```
* `khm ≈ nch·(ns − 6)` — размер гамильтониана (ns — число сплайнов).
* dbsr_hd3 хранит несколько плотных матриц khm×khm плюс рабочий массив
  DSYEVD: `hd_gb ≈ 1 + 4.6·khm²·8 Б`. khm = 11 000 → 5.7 ГБ; 31 000 → 36 ГБ;
  51 000 → 98 ГБ.
* Диагонализация — DSYEVD (патч pydbsr; в исходном DBSR — DSYEV с минимальным
  рабочим массивом, в 6 раз больше процессорного времени). Время ∝ khm³:
  11 000 — ~4.5 мин процессорного времени, 51 000 — ~7 ч.
* **Для матриц больше 32 000** DSYEVD нужен LAPACK с 64-битными целыми:
  `pip install scipy-openblas64` (в офлайн-архиве — `wheels/`). Без него
  dbsr_hd3 использует DSYEVR (в логе «DSYEVR used»), который на плохо
  обусловленных задачах бывает в разы медленнее. `pydbsr info` показывает,
  найдена ли библиотека.
* Временный файл матрицы `dbsr_mat.nnn` ≈ 0.5·khm²·8 Б.

Для Xe⁺ (67 состояний) J = 0: 67 каналов, khm ≈ 11 000, ~28 мин на волну
(dbsr_mat3 1 поток + dbsr_hd3 2 потока). С ростом J каналов больше
(до нескольких сотен) — самые большие волны определяют требования к памяти.

## `run_streamed` — потоковый режим

```python
sc.run_streamed(cores=64, mem_gb=200, hd_threads=16,
                cleanup=True,            # удалять dbsr_mat.nnn/int_bnk.nnn сразу после h.nnn
                skip_done=True,          # волны с готовым h.nnn пропускаются (перезапуск)
                scratch="~/pydbsr_tmp",  # быстрый диск для временных файлов
                scratch_gb=5)
```
* Каждая волна: dbsr_breit3 → dbsr_mat3 (1 ядро) → dbsr_hd3 (`hd_threads`
  потоков LAPACK). Волны идут одновременно, пока хватает ядер и памяти
  (`cores`, `mem_gb`); самые большие стартуют первыми.
* **Перезапуск:** прерванный расчёт (перезагрузка, нехватка памяти) продолжается
  тем же вызовом — готовые `h.nnn` пропускаются.
* **Упала одна волна** — остальные досчитываются, ошибка сразу в логе, в конце
  исключение со списком. Исправьте причину и вызовите снова.
* **scratch:** волна считается в быстрой папке, если её временные файлы
  помещаются в свободную часть `scratch_gb`; результаты сразу переносятся в
  рабочую папку. Волны крупнее — в рабочей папке.
* В конце — предупреждение, если состояния мишени взаимодействуют (см. [target.md](target.md)).

Обычный режим (все волны каждой программы по очереди): `sc.run()` или
`sc.run_breit(); sc.run_mat(); sc.run_hd()` с `Scattering(..., jobs=8, threads=4)`.
MPI-версии (если собраны): `Scattering(..., mpi=16)`.

## Что pydbsr делает за вас (и почему)

* **Мультиполи.** dbsr_mat3 по умолчанию отбрасывает интегралы Rᵏ с k > 7 —
  часть обмена для континуума с l ≥ 6. pydbsr передаёт каждой волне
  `mk = l_cont,max + l_bound,max` (`sc.multipole_max(klsp)`). Ограничить ради
  памяти: `Scattering(..., mk_max=12)`.
* **Ортогональность континуума корреляционным орбиталям** (`sc.orth_conditions()`),
  см. [target.md](target.md#корреляционные-орбитали-correlation).
* **Пороги.** С `exp_energies=True` энергии состояний в dbsr_hd3 заменяются на
  NIST (`thresholds`, `iexp=1`) — правильное положение порогов и резонансов.
  Это единственный эмпирический вход; `exp_energies=False` — чисто ab initio.
* **Проверка согласованности мишени:** `sc.target_errors()` → максимальные
  ⟨i|H|j⟩, ⟨i|j⟩ из `mat_log.nnn`.

## Параметры программ DBSR

`params={...}` → файл `dbsr_par` (читается всеми программами):
```python
sc = db.Scattering(tg, "scat", jmax=10, params={"mbreit": 1})   # брейтовское взаимодействие
```
`prep_args={...}` — аргументы dbsr_prep3 (`eps_ovl`, `eps_phys`, …),
`hd_args={...}` в `run_streamed` — аргументы dbsr_hd3. Список параметров —
в руководстве DBSR (`DBSR3/*/read_arg.f90` или `программа ?`).

## Возмущающие конфигурации (perturbers)

(N+1)-электронные связанные конфигурации, которые нельзя получить как
«мишень + континуум» (например, из-за ортогонализации), добавляются так:
```python
sc = db.Scattering(tg, "scat", jmax=10, perturbers=[(klsp, "path/pert_name")])
```
(`pert_name.c` / `pert_name.bsw` — как у состояний мишени).

## Связанные состояния (N+1)-системы

```python
bound = sc.bound_states(msol=50)     # dbsr_hd3 itype=-1 + dbound_tab
print(bound[0])                      # для Xe⁺: основное состояние Xe 5p⁶ ¹S₀
```
Хорошая проверка модели: для e + Xe⁺ нижний полюс 2J=0⁺ даёт потенциал
ионизации Xe 12.14 эВ (NIST 12.13).
